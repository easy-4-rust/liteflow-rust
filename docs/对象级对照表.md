# LiteFlow → liteflow-rust 对象级对照表（验收清单）

> 更新日期：2026-07-29
> 唯一基线：dromara/liteflow **v2.16.0**，共 **500 个生产 Java 对象**；
> 其中 `liteflow-core` 304 个。

本文档回答“每个 Java 对象落在哪个 Rust 文件”。文件命中只证明对象边界存在，
不证明方法、运行结果、错误、外部服务或生产语义已经完成；行为状态以
《语义迁移对照表》为准，名称例外以《对象名称一致性检查》为准。

## 目标工程结构（Cargo workspace）

```
liteflow-rust/
├── Cargo.toml                    # workspace 根
├── liteflow-core/                # 核心引擎 crate，src/ 下按 Java 包同名建目录

├── liteflow-benchmark/           # Java POM 声明的 8 个 benchmark 子 crate
└── liteflow-testcase-el/         # 29 个集成测试子 crate
```

## 命名与组织规则

1. 目录、文件名一律 snake_case（`flow/element/condition/then_condition.rs`）；
   文件内类型 PascalCase、方法 snake_case，参数名与 Java 一致。
2. **每个 .rs 文件只对应一个 Java 对象**；保留 Java 对象身份并转换为
   snake_case（`ICmpAroundAspect` → `i_cmp_around_aspect.rs`），避免与
   `spi.CmpAroundAspect` 合并。
3. `mod.rs` 只做模块声明与 re-export，**禁止定义任何类型/逻辑**；
   `lib.rs` 只做 crate 门面，**禁止堆放对象**；不允许出现 compat.rs。
4. Java 多层嵌套包只要求**最后一层目录**完全对齐
   （如 `flow/element/condition/` → `flow/element/condition/`）。
5. 每个文件头部必须有中文 doc 注释：说明对应 Java 类的全限定名、
   核心职责、与 Java 实现的差异；方法级中文注释从 Java 源码同步翻译。
6. Jackson → serde；Spring Boot → Vernal/Axum；
   ThreadLocal → Arc 共享上下文；CopyOnWriteHashMap → `Arc<HashMap>` 快照 + `RwLock` 复制发布；
   CompletableFuture → tokio JoinSet；Spring 容器 → 显式注册表。
